# delegacao.md — 角色与契约

角色：**编排者**（决策、拆分、审查、整合、与人沟通）、**重推理**（深度分析与对抗式审查）、**执行者**（实现一个产物）、**简单**（搜索、分诊、提取）。

## 派单
```
DISPATCH <id>
负责人: <一个子代理>   模型/强度: <x>   工具: <最小列表>
目标: <1 句话>
产物: <1 个输出路径>   （不得超出）
范围: 仓库/分支/提交，允许的文件；范围外 = 未验证
证据: <编排者将运行或阅读的命令或标准>
禁止: 密钥、credentials/、push、邮件、部署、删除
人工关口: <继续前需交回人类确认的内容>
预算: <最长时间与 token>
交付: 简短总结 + 证据（命令输出、文件:行号）
```

## 结构化交接（回报）
```
HANDOFF <id>
已完成: <改了什么，附路径>
证据: <命令输出 / 文件:行号>
未完成 / 受阻: <原因>
风险与未验证: <列表>
下一步: <1 行>
```

## 编排者规则
1. 对照证据阅读并核对所有输出。2. 不把密钥或客户数据转给不需要的人。3. 执行者没有发送、推送、部署或支付工具。4. C 级任务由上下文干净、且与执行者不同模型的对抗式审查者把关。5. 每个文件一个负责人，深度 1。6. 记录日志。7. 级别存疑即为 C。

## 何时委派
委派：广度任务、重复批量、独立审查（C 级必做）、会污染上下文的探索、负责人不同的并行工作。内联：S 级、单文件、决策、最终领域写作、依赖对话上下文的一切。
