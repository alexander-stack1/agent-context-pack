## 0. AI 必须如何使用本文件

1. 在提出布局、UI 文案、流程、组件或视觉审阅**之前**阅读本文件。
2. 视为**失败关闭**：若无法满足 MUST 标准，声明 `DOES NOT MEET` + 原因；不编造合规。
3. 交付时附上已填写的**收束清单**（第 7 节）。无清单 = 交付不完整。
4. 不复制作著全文。应用标准。仅将著作引为标准来源（例如「Norman：可供性」）。
5. 标准冲突时，优先此顺序：(1) 主操作清晰，(2) 降低认知负荷，(3) 视觉层级，(4) 美学。

## 1. 主原则（MUST）

### 1.1 显见操作（Krug + Norman）
- 屏幕须在 ≤3 个心智秒内回答：**这是什么**、**我能做什么**、**我在哪里**。
- 每屏（或每状态）一个**主操作**。次操作在视觉上从属。
- 控件须看起来像其所做之事（可供性）。当前状态须可感知（反馈）。
- 自然的控件→效果映射（例如手势/按钮与预期结果对齐）。

### 1.2 别让用户思考（Krug）
- 字面标签，不要耍聪明。避免内部黑话。
- 存在平台模式时用常规导航（iOS HIG / web）。
- 自解释 > 说明书。若需要屏上手册，流程已失败。
- 快乐路径无干扰。高级选项放在渐进披露之后。

### 1.3 心智模型与心理（Johnson + Yablonski）
- 为人的有限感知与记忆设计；不为系统模型设计。
- 减少同时选择（Hick）。目标对上下文足够大（Fitts）。
- 与用户已有知识一致（Jakob）——**在产品与平台内**。
- 把一起处理的内容分组（接近 / 相似律）。
- 避免过载：分块、层级、第一步更少字段。

### 1.4 层级与视觉工艺（Refactoring UI）
- 靠**大小、字重、颜色与间距**建层级；不靠装饰。
- 间距用一致刻度（例如 4/8）。对齐隐式网格。
- 正文对比可读。不要浅灰压浅灰。
- 颜色有功能：1 个品牌色做强调；状态（错误/成功/警告）可区分且不只靠颜色。
- 少用边框；优先用空间、轻阴影或差异背景分隔。
- 密度适境：mobile = 每屏更少；桌面可堆叠但留呼吸。

### 1.5 错误、恢复与信任（Norman + Johnson）
- 先防错再纠错（约束、安全默认、仅破坏性操作要确认）。
- 错误消息：发生了什么、为何（人话）、现在如何修。
- 破坏性操作：可能则可逆；否则显式确认并点名后果。
- 加载与空状态是 UI：永不死屏无下一步。

## 2. MUST-NOT（交付禁止）

- 把通用占位当终稿（「Lorem」「Click here」「Learn more」无对象）。
- 同一区域超过一个视觉并列的 CTA。
- 模态叠模态；不说该做什么的警告。
- 含义非通用时图标无标签。
- 表单索取系统已有或可稍后可选的数据。
- 拖延任务或隐藏状态的动画。
- 黑暗模式：假紧迫、隐藏退出、有害预勾选。
- 对比不足；图像上文字无遮罩。
- 无证据却编造可用性指标或「用户测试」。

## 3. 按交付类型的标准

### 3.1 线框 / 流程
- 列出屏幕与状态（空、加载、错误、成功、权限拒绝）。
- 标明主操作与 MVP 最少数据。
- 显式用户决策与流失点。

### 3.2 高保真 UI / App Store 单品
- 字体：最多 2 族；有限刻度（例如 3–5 号）。
- 复用组件具相同 padding 与圆角。
- iOS 安全区；可点目标 ≥ 44pt。
- 最低无障碍：适用时 Dynamic Type；控件标签；信息不只靠颜色。

### 3.3 界面文案
- 按钮动词 = 结果（「保存 PDF」，不是「OK」）。
- 屏幕标题 = 任务或对象，非营销。
- 错误与空状态微文案最后写，永不省略。

### 3.4 对已有屏幕的审阅
- 发现项报告为：`FINDING` | `OK` | `UNVERIFIED` | `NOT APPLICABLE`。
- 每个 `FINDING` 含：违反的标准（本指南章节）、屏上证据、最小修复。

## 5. 强制工作顺序（生成 UI）

1. **任务**：一句「用户在 Y 时能 X」。
2. **状态**：绘图前列全。
3. **结构**：层级与主操作（无颜色）。
4. **工艺**：字体、空间、颜色、组件。
5. **文案**：最终标签。
6. **压力**：空、错误、离线、首次打开、返回。
7. **清单**（第 7 节）。

步骤 1–3 前不要跳到颜色/风格。

---

## 6. 交付的自动拒收标准

若出现以下情况，AI 必须**重做**（不交付）：
- 主操作含糊；
- 清单缺失或 MUST 项空白；
- 占位文案；
- 未描述错误/空状态；
- 规格中对比或触控目标明显不足。

---

## 7. 收束清单（响应中强制）

复制并标记 `YES` / `NO` / `N/A`。每个 `NO` 需修复或 `DOES NOT MEET` 理由。

**清晰**
- [ ] 3 秒内清楚屏幕是什么与主操作
- [ ] 一个可见主 CTA；次操作从属
- [ ] 字面标签；无内部黑话

**交互**
- [ ] 控件有足够可供性/示能
- [ ] 操作有即时反馈（轻点、提交、保存）
- [ ] 破坏性有确认或撤销
- [ ] 状态：空 / 加载 / 错误 / 成功已描述

**认知**
- [ ] 当前步骤选择减至必要
- [ ] 与平台和产品模式一致
- [ ] 再认 > 记忆（可见选项、历史、默认）

**视觉**
- [ ] 清晰字体层级（≤5 个有用字号）
- [ ] 间距在一致刻度上
- [ ] 文字对比足够
- [ ] 颜色有功能；非纯美学
- [ ] 触控目标足够（mobile）

**伦理 / 滥用**
- [ ] 无黑暗模式
- [ ] 无捏造紧迫或内疚

**元**
- [ ] 屏幕任务用一句话声明
- [ ] 审阅时发现项标为 OK / FINDING / UNVERIFIED / NOT APPLICABLE
