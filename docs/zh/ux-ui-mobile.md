## 何时应用

- Landing/营销 mobile 断点（≤768px），**或**
- 带标签导航的原生应用 / PWA，**或**
- 手机上的聊天/智能体 UI。

若任务是完整 landing：先 `ux-ui-web-landing.md`（桌面），再用**本文件**做 mobile 布局。不要在 mobile 上用 3 栏网格。

---

## STEP 0 — MOBILE 闸门

1. 声明上下文：`landing-mobile` | `app-shell` | `chat-agent`。
2. 竖屏优先。横屏 = 加分，非默认。
3. 注意力短：每屏一任务；CTA 在首屏。
4. 配色 60-30-10（`ux-ui-INDEX.md`）。
5. 触控目标 ≥ 44×44 pt/px CSS。

## A. Mobile landing（相同解剖区块，不同布局）

### STEP M1 — Mobile 导航栏

**做**
- Logo 在左。
- 紧凑 CTA（「开始」/ 主操作）可见。
- 右侧汉堡放其余链接（Solutions、Pricing、FAQs…）。

**子规则**
- M-NAV-1: Mobile 顶部不要 6 个文字链接一行。
- M-NAV-2: 栏上 CTA = 主操作（不是「菜单」）。
- M-NAV-3: 打开菜单 = 清晰列表 + 显见关闭；无叠模态。

### STEP M2 — Mobile Hero（纵向堆叠）

强制顺序（自上而下）：

1. 标题（`[结果] — [异议]`）
2. 短副标题
3. **主 CTA（CTV）** ← 在视觉之前
4. 产品视觉

**子规则**
- M-HERO-1: CTA 在视觉之上（首屏）。
- M-HERO-2: 单列；文字不与 mockup 并排。
- M-HERO-3: 无需缩放即可读（正文 ≥ 16px）。

### STEP M3 — 内容区块

用例、痛点、为何、如何、收益、定价、证言、CTV、FAQ、页脚：

**子规则**
- M-LAY-1: **始终 1 列**。卡片堆叠。
- M-LAY-2: 定价 = 堆叠卡片；「最佳」方案在前或带清晰徽章。
- M-LAY-3: 证言 = 1 张可见卡 + 滑动（手势），不是 5 张照片并排。
- M-LAY-4: FAQ 全宽手风琴。
- M-LAY-5: 区块间留足间距；拇指需要呼吸空间。

### STEP M4 — Mobile landing 清单

- [ ] 导航栏有汉堡 + CTA
- [ ] Hero：标题 → CTA → 视觉
- [ ] 所有网格区块均为 1 列
- [ ] CTA 在首屏
- [ ] 字体可读；目标 ≥ 44pt
- [ ] 60-30-10；强调色仅用在 CTA

## B. Mobile 应用（产品壳）

### STEP M5 — 应用导航

**做**
- 主任务优先**底部标签栏**（3–5 个目的地）。
- 汉堡仅用于次级/设置，不用于核心路径。

**子规则**
- M-APP-1: 标签目的地 = 频繁任务；短标签 + 图标。
- M-APP-2: 活动标签视觉显见。
- M-APP-3: 不依赖悬停。

### STEP M6 — 触控交互

**子规则**
- M-TOUCH-1: 轻点 / 滑动 / 捏合；无可悬停专用可供性。
- M-TOUCH-2: 手指友好控件（≥ 44pt）；目标之间有间距。
- M-TOUCH-3: 被发现的手势带示能（或在 MVP 避免隐藏手势）。

### STEP M7 — 内容与注意力

**子规则**
- M-ATT-1: 每屏一个主操作。
- M-ATT-2: 尽量少打字（默认、选择器、自动完成、适用时 OCR/扫描）。
- M-ATT-3: 适配多种尺寸（安全区、刘海、打开键盘）。
- M-ATT-4: 短会话：保存状态；恢复时不必重做。

### STEP M8 — Mobile 应用清单

- [ ] 底部导航或有正当理由的平台模式
- [ ] 无悬停依赖
- [ ] 目标 ≥ 44pt；字体可读
- [ ] 快乐路径上打字最少
- [ ] 状态：空 / 加载 / 错误 / 离线
- [ ] 尊重安全区

## C. 聊天 / 对话智能体（mobile）

### STEP M9 — 聊天布局

**做**
- 页眉：智能体标题 + 操作（搜索/资料），不抢消息区。
- 历史用气泡（用户 vs 智能体），对比清晰。
- 底部固定输入：字段 + 发送；仅当真有语音时才可选麦克风。

**子规则**
- M-CHAT-1: 输入始终可及（键盘之上）。
- M-CHAT-2: 长智能体消息换行；行内 CTA 仅当它们就是操作时。
- M-CHAT-3: 无实现则不编造语音/麦克风。

### STEP M10 — 聊天清单

- [ ] 气泡可区分
- [ ] 底部输入稳定
- [ ] 发送目标 ≥ 44pt
- [ ] 发送错误可恢复

## D. MOBILE vs WEB 速查表（勿混淆）

| 维度 | MOBILE | WEB |
|----------|--------|-----|
| 导航 | 汉堡 + CTA；或应用底部标签 | 横向链接 + 始终可见 CTA |
| 布局 | 1 列 | 2–3 栏网格 |
| 交互 | 触控/手势；无悬停 | 点击 + 悬停 + 键盘 |
| 方向 | 竖屏优先 | 宽横屏 |
| 注意力 | 快速任务 | 更长探索 |
| Landing Hero | CTA **在**视觉**之前** | 视觉可并排；CTA 在首屏 |

---

## 自动拒收（mobile）

若出现以下情况则重做：
- mobile 上 3 栏网格；
- Hero CTA 在视觉之下；
- 顶部钉死桌面链接而无汉堡；
- 目标 < 44pt 无正当理由；
- 悬停是唯一示能。
